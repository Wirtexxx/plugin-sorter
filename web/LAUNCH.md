# Запуск сайта Plugin Sorter

Сайт публикуется на Cloudflare Pages. Cloudflare сам собирает его из GitHub при каждом изменении в `web/`, секреты и токены в репозитории не нужны. Шаги 1–4 не требуют домена. Названия пунктов в панели Cloudflare могут немного отличаться.

## Без домена

1. **Довести сайт до `main`.** Папка `web/` должна быть в `main`: слить `develop` в `main` через Pull Request. Новый релиз приложения для этого не нужен, он выходит только по тегу `v*`.

2. **Создать проект в Cloudflare.** Workers & Pages, Create, вкладка Pages, Connect to Git, выбрать `Wirtexxx/plugin-sorter`.

   | Настройка | Значение |
   |---|---|
   | Project name | `plugin-sorter` |
   | Production branch | `main` |
   | Framework preset | None |
   | Build command | `node build.mjs --release` |
   | Build output directory | `dist` |
   | Root directory | `web` |
   | Переменная `SKIP_DEPENDENCY_INSTALL` | `1` |

   Сборке не нужны зависимости, поэтому их установка отключена. Версия Node берётся из `web/.node-version`. В настройках сборки в Build watch paths указать `web/*`, чтобы правки приложения не пересобирали сайт.

3. **Проверить временный адрес.** Сайт откроется на `https://plugin-sorter.pages.dev` (имя может отличаться, если оно занято).
   - Открыть обе страницы, нажать «Скачать» и проверить настоящую форму Ko-fi.
   - Открыть несуществующий адрес: должна показаться страница 404.
   - Выполнить `curl -I https://plugin-sorter.pages.dev/`: должен быть заголовок `x-robots-tag: noindex`. Он не даёт Google проиндексировать временный адрес и не действует на настоящем домене.
   - Подтвердить в Ko-fi выплаты в Польшу и комиссии.

4. **Сверить тексты.**
   - Ячейки «Нет» и «Вручную» в таблице сравнения проверить на своей версии FL Studio. Особенно эти строки: их никто не сверял с FL Studio.
     - «Скрыть плагин сразу от всех DAW»
     - «Удалить плагин вместе с настройками, кэшами и следами установщика»
     - «Отправить старые версии и лишние копии в Корзину»
     - «Хранить лицензии в Связке ключей macOS»
     - «Экспортировать список плагинов в Markdown, CSV или JSON»
   - Текст от первого лица в блоке поддержки перечитать и поправить под себя.

5. **Скриншот «до».** Готово: `docs/screenshot-fl-picker-before.png` снят, `web/assets/picker-before.webp` собран и лежит в репозитории. Если снимок поменяется, положить новый файл на то же место и выполнить в `web/`: `npm run assets`. Размер и кадрирование должны совпадать с `docs/screenshot-fl-picker.png`, иначе сравнение «до/после» на странице будет выглядеть криво. На снимке смешанный пикер: у части плагинов картинки есть, многие показаны текстом. Текст блока говорит именно так, поэтому при замене снимка его нужно перечитать.

## С доменом

6. **Купить домен** `pluginsorter.com`. Удобнее всего в Cloudflare: Domains, Register. Если выбрать другое имя, поменять `domain` в `web/site.config.json`.

7. **Подключить домен.** В проекте Pages: Custom domains, Set up a custom domain, добавить `pluginsorter.com` и `www.pluginsorter.com`. Если домен куплен в Cloudflare, DNS-записи создадутся сами. Затем настроить перенаправление с `www` на основной адрес: Rules, Redirect Rules.

8. **Search Console.** Подключить `pluginsorter.com` через DNS-запись TXT и отправить `https://pluginsorter.com/sitemap.xml`.

9. **Обновить ссылки.** `homepage` репозитория и ссылки на сайт в обоих README. `.github/FUNDING.yml` уже настроен.

## Что настроено в файлах

- `web/src/_headers`: кэш картинок и шрифтов на 30 дней, заголовки безопасности, запрет индексации `*.pages.dev`.
- Ссылки на стили и скрипт меняются вместе с их содержимым, поэтому посетители сразу получают новую версию. Если заменить картинку, но оставить имя файла, вернувшиеся посетители могут видеть старую до 30 дней: в таком случае лучше дать файлу новое имя.
- `404.html` и `ru/404.html`: без них Cloudflare на любой неизвестный адрес отдавал бы главную страницу.

## Проверка сборки для публикации

```
cd web && node build.mjs --release
```

Сборка проходит. Если удалить `web/assets/picker-before.webp` или другую картинку со страницы, команда упадёт с `Missing <файл>`: это правильное поведение.
