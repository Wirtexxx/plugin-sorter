# Запуск сайта Plugin Sorter

Сайт собран и протестирован, но не опубликован. Публикация включается переменной репозитория `SITE_LIVE=true`: пока она не равна `true`, job `deploy` в `.github/workflows/web.yml` не запускается. Ниже шаги автора по порядку.

1. **Купить домен** `pluginsorter.com`.

2. **Скриншот «до».** Готово: `docs/screenshot-fl-picker-before.png` снят, `web/assets/picker-before.webp` собран и лежит в репозитории. Если снимок поменяется, положить новый файл на то же место и выполнить в `web/`: `npm run assets`. Размер и кадрирование должны совпадать с `docs/screenshot-fl-picker.png`, иначе сравнение «до/после» на странице будет выглядеть криво. На снимке смешанный пикер: у части плагинов картинки есть, многие показаны текстом. Текст блока говорит именно так, поэтому при замене снимка его нужно перечитать.

3. **Проверить Ko-fi.** Ko-fi уже создан, ссылки лежат в `web/site.config.json`. Собрать страницу (`npm run build`, затем `npm run preview`) и открыть в браузере настоящую форму Ko-fi: она должна отображаться и вести в платёжный сценарий. Подтвердить выплаты в Польшу и комиссии.

4. **Сверить тексты.**
   - Ячейки «Нет» и «Вручную» в таблице сравнения проверить на своей версии FL Studio. Особенно эти строки: их никто не сверял с FL Studio.
     - «Скрыть плагин сразу от всех DAW»
     - «Удалить плагин вместе с настройками, кэшами и следами установщика»
     - «Отправить старые версии и лишние копии в Корзину»
     - «Хранить лицензии в Связке ключей macOS»
     - «Экспортировать список плагинов в Markdown, CSV или JSON»
   - Текст от первого лица в блоке поддержки перечитать и поправить под себя.

5. **Домен и DNS.** Подтвердить домен в настройках профиля GitHub: значок профиля, Settings, Pages, Verified domains. Это не настройки репозитория; если репозиторий переедет в организацию, тот же раздел находится в настройках организации. Затем у регистратора создать записи.
   - `A` для апекса: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - `AAAA` для апекса: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`
   - `CNAME` для `www`: `wirtexxx.github.io` (сам домен, без имени репозитория)

   Значения сверены с текущей документацией GitHub Pages (2026-11-05). Перед использованием проверить их ещё раз: https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site

6. **Включить публикацию.** Settings, Pages, Source: GitHub Actions. Затем Settings, Secrets and variables, Actions, Variables: `SITE_LIVE=true`. Сама переменная запуск не начинает. Ветка с сайтом должна сначала попасть в `main`, затем открыть Actions, Web, Run workflow и выбрать `main`. Когда публикация пройдёт, указать custom domain и включить Enforce HTTPS (после выпуска сертификата).

7. **Search Console.** Подключить `pluginsorter.com` через DNS-запись TXT и отправить `sitemap.xml`.

8. **Обновить ссылки.** `homepage` репозитория, ссылки в обоих README и `.github/FUNDING.yml` (`ko_fi` там уже записан).

## Проверка сборки для публикации

```
cd web && node build.mjs --release
```

Сборка проходит. Если удалить `web/assets/picker-before.webp` или другую картинку со страницы, команда упадёт с `Missing <файл>`: это правильное поведение.
